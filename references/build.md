# 施工：从设计到能过审的世界

> 三层落点：**编辑器 AI → Unity SDK → 平台服务**。
> 先把预算定死，再开始做内容。做完再优化，基本等于重做。
> 完整平台事实、口径冲突与引用见 `references/platform.md`。

---

## 0. 三层落点

| 层 | 你在这里做什么 | 工具/入口 | 产物 |
|-|-|-|-|
| 编辑器 AI | 地图、模型、音效、特效、Agent 生成 | 造世界编辑器（AI 地图/资产） | 地形底板、GLB、资产库 |
| Unity SDK | 场景、组件、Lua、UI、联网、DS | Unity + Douyin World SDK | 可运行工程、网络对象、界面 |
| 平台服务 | 分享、复访、关注、奖励、发布、审核、商业化 | 创作后台/API | 上线世界、运营数据 |

**口径优先级**：官方文档 > 二手教程。两者冲突时，先按更严格的一边做，再把差异记进实验记录。

| 内存 | **< 1400MB** |
| 网络对象 | **< 8000**（硬上限 10000） |

### 1.3 人数与存储

| 项 | 上限 |

### 1.4 星光预算

| 项 | 数值 |

## 2. 编辑器层：AI 地图与资产

### 2.1 地图四步

| 步 | 做什么 | 注意 |
|-|-|-|
| 1 | 生成地图预览图（提示词/参考图） | 不满意就重来，别进 3D |
| 2 | 地形生成（高度图） | 15–30 分钟，高峰期更久 |
| 3 | 解析地表物体 | 单图低矮植被 ≤16 种 |
| 4 | 导入主世界场景 | 成为地形底板，可再用手刷调整 |

提示词三要素：地形类型、环境风格、具体细节（河流/山高/植被密度）。

### 2.2 资产

| 方式 | 什么时候用 | 参考耗时 |
|-|-|-|
| 一体铸造 | 静态建筑/道具/植物 | 约 3 分钟 |
| 模块组装 | 会动的部件（轮子/机关/载具） | 约 10 分钟 |
| Agent / VibeCoding | 需要行为逻辑、想用自然语言改玩法 | 按任务 |
| MIX | 多个资产组合成玩法 | 按任务 |

先判断「要不要动」，再选生成方式，能省一半返工。
模型/地图 Prompt 的写法和负向约束见 `references/prompts.md`。

### 2.3 编辑器生成纪律

> 具体在哪个面板、点什么，见 `references/editor-guide.md`。

| 能力 | 怎么用 | 备注 |
|-|-|-|
| 项目/资源/世界参数 | 编辑器 UI | 确认目标项目再改 |
| 地图生成 | AI 地图四步 | 预览图确认后再 3D |
| 模型生成 | 一体铸造 / 模块组装 | 先看面数/贴图预算 |
| 预览运行 | 本地运行 + 手机预览 | 发布前各跑一遍 |
| 发布/审核 | 创作后台 | 手动提交，预留 1–3 天 |
| 水体/Prefab/音效 | 编辑器 UI | 不在自动化范围 |

生成纪律：

- 一次只改一个变量（风格/结构/面数）。
- 保留参数和结果，写进 `05-build-plan.md` 的生成记录。
- 真实生成前确认星光余额和单轮上限。
- 不在 L1 阶段生成精模、动画、大场景。

## 3. Unity SDK 层：组件、Lua、联网

### 3.1 场景根

每个场景只能有 **1 个 `Douyin World Root`**，它负责：

- 出生点（随机/首个/顺序）、重生高度（默认 -100m）、游客出生点
- 玩家速度（默认 3m/s）、跳跃高度（默认 1m）
- 自定义相机（不关联的自建相机会在上传后被删）
- 网络对象生成配置
- 横竖屏支持
- 流式加载（构建期固化，运行时只读）

### 3.2 组件选型

| 需求 | 直接用 | 不要自己写 |
|-|-|-|
| 靠近交互 | `DouyinInteractor` | 自己射线检测 |
| 拿起/放下 | `DouyinPickUp` | 自己写抓取 |
| 坐下 | `DouyinSeat` | 自己写姿态 |
| 同步物体 | `Douyin Object Sync` | 手写 Transform 同步 |
| 头顶对话 | `DouyinNameBoard` | 自建 TextMesh |
| 关注作者 | `DouyinFollowPlane` | 自建关注 UI |
| 视频 | `Douyin Video Player` | 自建播放器 |
| 传送 | `Douyin World Portal` | 自己切场景 |
| 精灵发放 | `Douyin Pet Pedestal` | 自己发奖 |
| 水域 | 水域组件 | 自己写浮力 |

### 3.3 C# 还是 Lua

- **不能新增自定义 C# 脚本**：SDK 处理上传时会剔除非 SDK 的 C# 脚本/第三方插件。
- 玩法逻辑写在 **Lua**，挂到 `Douyin Script` 上；Lua Prompt 模板见 `templates/lua-prompt.md`。
- Lua 组件可读可改；C# 组件只能配 Inspector。
- 复杂逻辑尽量集中在**一个** GameObject，减少跨对象主权差异。

### 3.4 联网模式怎么选

| 你的世界 | 选 Shared Mod | 选 DS |
|-|-|-|
| 休闲社交、拍照、剧情、跑酷 | ✅ |  |
| 低难度合作、无付费、无排名奖励 | ✅ |  |
| 有付费、稀有资产、公平竞技 |  | ✅ |
| 需要防作弊、服务端校验 |  | ✅ |
| 商业化 | ❌ | ✅ 必须 |

核心规则：

- **容量是配置项**：5v5 设 10、15v15 设 30、解谜/陪伴 2–8、派对 20–30；可多房间并行。竞技的难点是 DS/服务端判定/匹配，不是人数。
- 动态创建/销毁网络对象用 `NetSpawn` / `NetDestroy`，不要用 `Instantiate` / `Destroy`。
- 改同步变量前先 `HasOwnership()`；只有主权方能写。
- 主权会因切后台/断线/退房转移，不要设计「永久持有」。
- 同步变量约 70–120ms 延迟；核心状态别用 RPC 兜底。
- `RemoteEvent` / `RemoteFunction` 只用于 DS。
- 断线 5 秒判定，约 30 秒重连；重连走 `OnPlayerRejoined`。

### 3.5 数据存储

- 单世界 100MB；单 DataStore 1000 键；Ordered 5000 键。
- 900 次/分钟，峰值 1800。
- 用户数据不要塞进一个「按属性」的 DataStore；按用户分片。
- 商业化：所有存储逻辑必须在 DS，客户端不许碰。

### 3.6 UI

- 三方主按钮 0–5 个；图标 ≤40×40；标题 ≤4 字；字号 10pt。
- 常驻功能 1–2 个，占用 <70%。
- 不覆盖小火人区、官方社交区、HUD。
- 横屏 2532×1170，竖屏 1170×2532；弹窗要有遮罩。
- 先做「手机竖屏 5 秒能读懂」的版本，再考虑横屏扩展。

## 4. 平台服务层：发布、分享、运营

### 4.1 发布物料

| 项 | 要求 |
|-|-|
| 名称 | 4–20 字符（按更严口径） |
| 描述 | 10–60 字符（按更严口径） |
| 封面 | 1125×630；icon 1800×1800、338×338 |
| 人数 | ≤30 |
| 标签 | 按玩法/场景/人群选，影响推荐 |
| Feed 卡 | 9:16、10–15s、≤20MB、无人声 BGM、不加字幕/特效 |

### 4.2 发布前检查

- [ ] 出生点 ≥1，不悬空/不卡墙/朝向主玩法区/多人分散/不在动态物体上
- [ ] 无穿模、无 Z-Fighting、无半悬空
- [ ] 本地运行 + 手机预览各跑一遍
- [ ] ≥2 位测试员走过首轮
- [ ] 资源检查通过（容量/光源/资源规范）
- [ ] 名称/描述/封面/标签一致且合规
- [ ] Feed 卡 9:16、10–15s、≤20MB；首 3 秒有动作
- [ ] 无第三方 IP、品牌 logo、真人肖像、未授权音乐、二维码
- [ ] 商业化：DS + 代码审查 + 兑换码 + 客诉时效

### 4.3 分享与复访

- IM 卡：标题 ≤13 字符，模板需提前配置并审核。
- 图片分享：168×264（安卓）/ 168×224（iOS），系统在结算/拍照点生成。
- 侧边栏：`enterFrom = 1`，可做每日/限时复访奖励。
- 邀请：`inviterOpenID` 判断被邀请者，双向奖励。
- 关注：官方组件只能关注作者，放在结算/出口。
- 传送门：只能去已发布世界，仅线上生效。

## 5. 范围阶梯（带预算门）

| 级别 | 内容 | 完成定义 | 预算门 |
|-|-|-|-|
| L0 纸面 | 画布 + 3 分钟脚本 + 预算估算 | 3 个目标玩家听懂并说出下一步 | 无 |
| L1 灰盒 | 1 张地图 + 3 个交互点 + 1 条闭环 | 3 个陌生人无提示完成一轮 | 容量/光源/资源检查无报错，留 ≥50% 余量 |
| L2 可玩 | 进度 + 1 个社交 + 1 个分享物 | 第 2 次愿意来，能生成分享图 | 按目标容量测试（5v5=10），FPS/内存达标 |
| L3 内容 | 美术/音效/文本/第二区域 | 截图可宣传，无穿帮 | 资源规范全绿 |
| L4 运营 | 首周活动、榜单、更新、侧边栏/邀请 | 首周排期可执行 | 审核通过 |

规则：

- L1 没过，不进 L2。
- L3 的美术不能修复 L1 的循环问题。
- 时间紧时砍 L3，不砍 L1/L2。

## 6. 任务单格式

每条任务必须可验收、可回退：

```md
### T03 首轮循环：捡瓶子 → 换贴纸

- 层级：Unity SDK（Lua + UI + 拾取组件）
- 落点：DouyinPickUp + Douyin Script + UI
- 预算：3 个网络对象、1 个材质、0 个动态光
- 依赖：T01 地图点位、T02 瓶子模型
- 输入：3 个点位、6 个贴纸图标
- 步骤：
  1. 3 个点位放可拾取瓶子（自动挂同步）
  2. 拾取后 UI +1、播放音效
  3. 集满 3 个解锁 1 张随机贴纸
- 生成 Prompt：见 templates/lua-prompt.md（或 asset-prompt.md / agent-prompt.md）
- 完成定义：玩家 60 秒内完成 1 次，UI 有 +1 反馈
- 验证：本地跑 3 次 + 手机预览 1 次 + 1 个新玩家
- 回退：固定点位 + 无动画 + 无音效
- 预估：0.5 天
```

粒度：**≤0.5 天**。超过继续拆。

## 7. 风险与回退

| 风险 | 触发信号 | 回退 |
|-|-|-|
| 资源超 700MB | 资源检查失败 | 复用官方资产、减贴图、合并材质 |
| 面数超 130 万 | 容量红/掉帧 | 低模、LOD、砍远景 |
| 动态光超 8 | 夜景发灰/掉帧 | 改烘焙、用 emissive 假光 |
| 网络对象超 8000 | 房间卡顿 | 对象池、减少同步物件、合并逻辑 |
| 主权频繁转移 | 玩家切后台后状态乱 | 不依赖单主权长持有；关键结算走 DS |
| 手机掉帧 | 预览 <30 FPS | 关实时阴影、降贴图、开流式 |
| 审核驳回 | 出生点/穿模/IP/文案 | 按自查表逐项修，预留 1–3 天 |
| 星光烧太快 | 生成多次不满意 | 先预览图/白模，再精修 |
| C# 脚本被剔 | 上传后逻辑丢失 | 全部逻辑改 Lua |
| 商业化卡审 | 无 DS/无兑换码/代码审查 | 第一天按 DS 架构 |
